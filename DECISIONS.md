# Журнал решений

Как проект пришёл к нынешнему виду: какие проблемы нашли, по каким данным, что решили и что это дало.
README — это результат и цифры; здесь — путь к ним. Даты: 26–28 ноября 2026.

Общий принцип, к которому пришли по ходу: **модель понимает живой язык (опечатки, сленг, казахский),
код сверяет то, что проверяется однозначно**. Каждую правку мерили отдельно и не подгоняли ожидания под ответы модели.

## 1. Каталог был частично из памяти модели

**Проблема.** При аудите Common автопроверка предложила сверить «Айку» (2019, 80 мин), а пример из раздатки
(`films_kz_example.json`, источник IMDb) давал другие цифры для «Жаужүрек мың бала» и «Рэкетира».
**Данные.** Сверка с Wikidata: «Гагарин (2020, Казахстан)» не существует (под этим названием — только мультфильм 1994 года);
Мың бала 90 → 132 мин; Айка 2019 → 2018, 80 → 114 мин; Рэкетир 90 → 80; Кочевник 112 → 122; «Москва слезам не верит» 150 → 140;
«Иван Васильевич» 93 → 88; у «Ульжан» в странах нет Казахстана. Опыт с памятью модели насчитал 4/10 «ошибок модели»,
но минимум в двух случаях модель была ближе к источнику, чем каталог (Мың бала: 133 мин против 90, источник 132;
Айка: год 2018 против 2019).
**Решение.** `build_catalog.py`: год, минуты, страны, языки берутся из Wikidata и приводятся к словам каталога кодом;
у каждого фильма `source`. «Гагарин» заменён на «Келинку Сабину» (2014, комедия, героиня из Алматы — по en.wikipedia).
У «Келін» в Wikidata нет языка: по en.wikipedia фильм без речи → `без слов` со второй ссылкой в `OVERRIDES`.
**Эффект.** Ментор может сверить любой фильм по ссылке. Опыт с памятью пересчитан на исправленном каталоге: 5/10.
**Осталось.** Год «Мың бала» в Wikidata — 2011 (самая ранняя дата), а прокат в Казахстане — 2012.

## 2. Wikidata ограничила SPARQL

**Проблема.** Во время аварии query.wikidata.org отвечал 429 «1 req / min»; частые повторы продлевали блок.
**Решение.** `build_catalog.py` переведён на API сущностей (`wbgetentities`, до 50 фильмов за запрос) с подписями стран и языков
отдельным запросом. Ранги Wikidata соблюдаются: `deprecated` не берём, `preferred` важнее `normal`.
**Эффект.** Факты совпали со SPARQL-версией один в один (разница только в порядке стран). Попутно поймали ошибку правила
«брать меньшую длительность»: у «Гарри Поттера» 142 мин — устаревшее (`deprecated`) значение, верное — 152.

## 3. «Нарушений условий 0» — слепое пятно

**Проблема.** В Rare код после ответа сверяет фильмы с фильтрами, которые разобрала **сама модель**.
Если модель потеряла условие («до двух часов»), счётчик честно покажет 0 — а пользователь получит фильм на 150 минут.
**Данные.** В замере на 33 запросах «отсёк код» = 0 у обеих моделей, но у qwen 6 показанных фильмов нарушали настоящие
условия: «әуенді емес, қазақша тарихи драма» → «Рэкетир» и «Шал» (не исторические), «русская криминальная драма» → «Кукушка».
**Решение.** У каждого запроса в `queries.json` — эталон `conditions`: условия, которые в запросе есть на самом деле.
`check.py` считает нарушения в выдаче против эталона и точность разбора: совпали ли **кандидаты** по фильтрам модели и по эталону
(так «2031» как `year_from` или как `year_from+year_to` засчитываются одинаково).
**Эффект.** Стало видно, где теряет модель — на разборе или на выборе. Без этого все дальнейшие правки было бы нечем мерить.

## 4. qwen принимал страну за язык

**Проблема.** «Французская комедия» → язык `французский`, «японский мультфильм» → `японский`, «казахстанское кино» → `казахский`.
Лишний язык выкидывает почти весь каталог → пустой подбор → `no_match`.
**Данные.** Разбор журнала по полям: лишний `languages` в 40 из 99 ответов qwen. Правило «страна — не язык» в промпте было,
4B-модель его не держит.
**Решение.** Код оставляет язык, только если он назван языковым оборотом: «на казахском», «по-английски», «қазақша», «қазақ тілінде».
**Эффект.** Разбор qwen против эталона 42% → 76% (только эта правка, `filters_eval.py`). На 33 запросах проверка совпала с эталоном 33/33.

## 5. qwen не знал казахские жанры и копировал примеры

**Проблема.** Словарь жанров русский; qwen не знал, что тарихи = исторический, әуенді = мюзикл, отбасылық = семейный,
қорқынышты = ужасы. «Әуенді емес» он превращал в «не мелодрама» — слово «мелодрама» стояло в обоих примерах промпта.
**Решение.** В промпт фильтров: казахские слова жанров, правило «X емес» (по-казахски отрицание стоит после слова),
правило для конкретного года, три новых примера не из тестового набора и без повторяющихся слов.
**Эффект.** Только промпт — 80%; вместе с проверкой языка — 91% у qwen; облако 93% → 97%.

## 6. Опечатки ломали проверку языка

**Проблема.** Проверка языка из №4 — регулярные выражения; на «на англиском», «казакша», «қазакша», «по англицки», «на каз. языке»
она выкидывала язык, который человек на самом деле просил. Из 12 вариантов опечаток код узнавал 4.
**Почему.** Код сам пытался *понять* язык — то, что хорошо умеет модель.
**Решение.** Цитата-доказательство: модель возвращает `language_quote` — фразу из запроса дословно, с опечатками.
Код проверяет три простые вещи: фраза есть в запросе (не выдумана); у неё форма языкового оборота, а не прилагательного страны;
первые буквы совпадают с языком (каз / қаз / kaz → казахский). Нет цитаты — запасной путь через оборот в запросе.
Плюс 9 запросов «как пишут люди» в наборе: «чо посмотреть на казахкском до 2 часов», «мульт без ужастиков», «kazaksha drama» и др.
**Эффект.** На 42 запросах: без цитаты разбор qwen 81%, опечатки 8/18; с цитатой 89%, 16/18. В финальном замере
подбор на запросах с опечатками у qwen 30/30, у облака 28/30.

## 7. «Казашка жапондых аниме»

**Проблема.** Три сложности в трёх словах: «казашка» по-русски — «казахская женщина», но здесь, скорее всего, опечатка
в «қазақша»; «жапондых» — казахское «японский» с опечаткой (страна, не язык); «аниме» — такого жанра в каталоге нет.
**Данные.** luna поняла «казашка» как язык и дала цитату, но код её отклонил (не похоже на форму «…ша») → условие потерялось →
показаны «Унесённые призраками», не на казахском.
**Решение.** Нечёткое сравнение: слово цитаты без казахских букв (қ→к, ә→а …) отличается от «қазақша» не больше чем на одну
правку, включая перестановку соседних букв (Дамерау–Левенштейн ≤ 1): «каза**шк**а» ↔ «каза**кш**а». «Фильм про казашку» —
две правки, не проходит. Оба варианта запроса добавлены в набор.
**Эффект.** Код принимает. Но в финальном замере luna в 2 прогонах из 3 сама не увидела в «казашка» язык — это и есть
2 нарушения против эталона у облака. Слово действительно двусмысленное; честно оставлено как есть.

## 8. «Аниме на казахском» — ограничение данных

**Проблема.** Даже при идеальном разборе такой запрос не выполним: `languages` в каталоге — **язык оригинала** (Wikidata P364),
а «на казахском» про аниме означает озвучку. Данных об озвучках нет.
**Решение.** Описано в README и SPEC; эталон — язык казахский + мультфильм → пусто → `no_match`.
**Эффект.** Программа не выдумывает «казахское аниме», а говорит, что такого нет.

## 9. Фильтр по рейтингу Rotten Tomatoes

**Идея.** Запросы вида «то, что хвалят критики». Скрейпить Rotten Tomatoes нельзя (правила сайта), открытого API нет.
**Решение.** Рейтинг из Wikidata: P444 с квалификатором P447 = Rotten Tomatoes (Tomatometer, %). Поле `rotten_tomatoes` в каталоге,
`min_rating` в `Filters` (по умолчанию `None` — контракт инструкции это допускает). Нет рейтинга в источнике → под `min_rating`
фильм не проходит: условие нечем проверить. Карточка печатает рейтинг.
**Эффект.** Рейтинг есть у 49 из 56 фильмов. Три запроса про рейтинг (один на казахском), облако проходит все.
**Осталось.** Нет рейтинга у шести из десяти казахстанских фильмов — для казахского кино фильтр почти бесполезен.

## 10. Узкие ожидания не подгоняли

**Проблема.** «Как Интерстеллар, но не про космос»: облако выбирает «Начало», «Матрицу» — разумно, но в `must` только «Прибытие».
«Семейный мультфильм, без ужасов»: «Душа», «Зверополис» подходят под эталон, но не в `must`.
**Решение.** Оставить ожидания как были записаны до прогонов и описать в README. Иначе набор подстраивается под модель и
перестаёт что-то мерить.
**Исключение, честно.** У «қазақша отбасылық фильм» ожидание сменили на `no_match` до первого замера Rare: в каталоге нет
казахоязычного фильма с жанром «семейный».

## 11. qwen без Structured Outputs

**Проблема.** Ollama отвечает 501 на `parse` → JSON текстом. qwen иногда оборачивает его в ```json, пишет рассуждение перед ним
или вообще формат `<max_minutes>: 120` в стиле наших тегов.
**Решение.** Запасной путь `create` → `extract_json` (ограды, обрезанный хвост) → проверка схемой; если JSON нет —
`tagged_fields` разбирает строки `<поле>: значение` для полей схемы, дальше та же проверка схемой.
**Эффект.** Сбоев разбора фильтров у qwen 2/30 → 0/30. Ответы шага выбора, не прошедшие схему: 6 из 99 запросов
в первом замере → 2 из 132 в финальном (пользователь при этом видит `invalid`, а не мусор).

## 12. Шум в фильтрах qwen

**Проблема.** qwen иногда пишет в `must_genres` весь словарь из 15 жанров («американский фильм 90-х») или кладёт жанр и в
обязательные, и в исключения («комедия емес» → must комедия).
**Решение.** `normalize_filters`: слово не из каталога отбрасывается; жанр из исключений убирается из обязательных;
больше трёх обязательных жанров = это словарь, а не условие; `min_rating` 1–10 переводится в проценты.
**Эффект.** Такой мусор больше не обнуляет подбор. Все правила покрыты тестами в `tests/test_filters.py`.

## Как повторить замеры

```bash
uv run check.py --runs 3 && uv run check.py --local --runs 3   # полный замер, пишет calls.jsonl
uv run show.py compare                                          # таблица моделей из журнала
uv run filters_eval.py --local --passes 2                       # только разбор, без журнала
uv run filters_eval.py --local --no-quote                       # без цитаты-доказательства
uv run filters_eval.py --local --no-guard                       # без проверки языка кодом
```

Промежуточные цифры из записей 4–6 получены `filters_eval.py` (в `calls.jsonl` не пишет); цифры итогов — из журнала.
