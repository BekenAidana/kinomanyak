# Киноманьяк

**Достигнутые уровни:** Common

Подбор 1–3 фильмов под сложный запрос **только** из локального `films.json`.  
Модель возвращает `film_id` + `why`; title / year / minutes / description печатает код из каталога.

Каркас: лекция 3 (fridge-chef) + семинар 3 (guardrails, cases, журнал).

## Запуск

Нужны [uv](https://docs.astral.sh/uv/) и ключ OpenAI. Локальный qwen — через [Ollama](https://ollama.com) (`ollama pull qwen3.5:4b`).

```bash
uv sync
cp .env.example .env   # впишите OPENAI_API_KEY
uv run kino.py "что посмотреть с мамой на казахском, до двух часов"
uv run show.py
uv run check.py          # весь queries.json на gpt-6-luna
uv run check.py --local  # тот же набор на qwen3.5:4b
uv run memory_probe.py   # опыт с памятью модели
uv run build_catalog.py  # сверить каталог с Wikidata
uv run pytest -q
```

`kino.py` как `chef.py` на лекции: **без флагов** сначала `gpt-6-luna` (`reasoning_effort=medium`, так же ходит `check.py`), потом `qwen3.5:4b` (`reasoning_effort=none`).  
Облако — `parse` (Structured Outputs). Если Ollama даёт 501 — повтор через обычный `create`, JSON проверяем схемой `Choice` сами.  
Без Ollama вторая модель — «Нет связи с сервером».  
`check.py --local` — прогон набора только на qwen.

| Лекция / семинар | У нас | Зачем |

| `calls.jsonl` + `show.py` | то же | журнал исходов, токенов, $ |
| `cases.py` | `queries.json` | запросы + `expect` |

| `test_guardrails.py` | `tests/test_pick.py` | pytest без сети |
| каталог | `films.json` + `canon.py` | факты не из памяти LLM; словарь под Epic |

### Guardrails

Промпт не гарантирует защиту. Код:

1. system ≠ данные; `<каталог>` / `<запрос>` — только данные.
2. Схема `Choice`: `status` ok \| no_match, `picks[{film_id, why}]`. Схема ≠ правда.
3. Allow-list: только id из переданного `films`, без повторов, ≤3.
4. Чужой id → весь ответ `invalid`, пользователь **ничего** не видит; id в `rejected` (как в инструкции).
5. Печать карточки из каталога; `why` — от модели.

Порядок в `pick`: API → length → refusal → schema → status → allow-list → печать → журнал.

### Журнал

В `calls.jsonl` на каждый вызов: модель, **компактный** request (текст запроса + список id, не весь каталог), outcome, секунды, usage/$.

```bash
uv run show.py        # последние 10
uv run show.py all
```

### `expect` в `queries.json`

- `must` — среди picks должен быть **хотя бы один** id из списка
- `forbid` — ни одного из списка
- `no_match` — исход ровно `no_match`
- без `expect` — на счётчик pass/total не влияет

## Каталог

**Источник фактов: [Wikidata](https://www.wikidata.org)** (CC0). У каждого фильма поле `source` — ссылка на его запись.

- `films.json`: 56 фильмов, 9 с «Казахстан» в `countries` (у «Ульжан» по Wikidata только Франция и Германия).
- `year` (P577, самый ранний год), `minutes` (P2047, значение лучшего ранга), `countries` (P495), `languages` (P364)
  забирает [build_catalog.py](build_catalog.py) одним SPARQL-запросом и приводит к словам каталога в коде
  («Соединённые Штаты Америки» → «США», «английский язык» → «английский»). Из памяти модели ничего не берётся.
- Где в Wikidata поля нет, значение и второй источник записаны в `OVERRIDES` скрипта:
  у «Келін» нет языка — фильм снят без речи ([en.wikipedia](https://en.wikipedia.org/wiki/Kelin_(film))), в каталоге `без слов`.
- Руками (и моделью) написаны только `title`, `genres`, `description` (1–2 предложения по-русски по статье Википедии).
- Обновить факты: `uv run build_catalog.py` (показать расхождения) / `uv run build_catalog.py --write`.
- `canon.py` — словарь жанров под Epic; `pick` его не импортирует.

## Пять вопросов лекции 1

1. **Какая цель у программы?**  
   Дать безопасный ответ на сложный запрос о кино без выдуманных фильмов.

2. **Как решить задачу без ML?**  
   Правила и фильтры по полям каталога (язык, минуты, жанр). Не хватает семантики вроде «как Интерстеллар, но не про космос».

3. **Какие данные нужны?**  
   Локальный `films.json`: id, title, year, minutes, genres, countries, languages, description.

4. **Что выдаёт программа?**  
   1–3 карточки из каталога или `no_match` / сообщение об ошибке; журнал `calls.jsonl`.

5. **Какова цена ошибки?**  
   Показать несуществующий фильм — потерять доверие (как список книг Chicago Sun-Times); поэтому id сверяет код.

## Ответы на вопросы задания

1. **Почему программа сверяет id, хотя название понятнее? Сколько расхождений дал опыт с памятью модели?**
   Название неоднозначно (два «Гагарина», «Келін» и «Келинка Сабина»), модель может написать его по-своему или выдумать;
   id сравнивается с каталогом точно. Опыт с памятью: **5/10** расхождений по году и длительности.
   Поэтому карточку печатает код из каталога: [kino.py:163-172](kino.py#L163-L172), сравнение — [memory_probe.py](memory_probe.py).

2. **Что будет, если модель вернёт `film_id`, которого нет в каталоге? Какие строки кода это ловят?**
   Allow-list в [kino.py:135-160](kino.py#L135-L160) складывает чужой id в `rejected`; ветка
   [kino.py:330-335](kino.py#L330-L335) пишет в журнал исход `invalid` с `rejected` и возвращает `("invalid", [])` —
   пользователь не видит ни одного фильма из этого ответа. Тест: `test_alien_id_invalid_and_rejected` в [tests/test_pick.py](tests/test_pick.py).

3. **Чем «модель ответила без ошибки» отличается от «модель подобрала верный фильм»? Как это видно в `check.py`?**
   Без ошибки — исход `ok`/`no_match`, схема разобрана, id из каталога. Верный фильм — в ответе есть id из `must`,
   нет id из `forbid`, `no_match` там, где ответа нет. Это проверяет [check.py:33-55](check.py#L33-L55),
   отметки ✅/❌ — [check.py:95-103](check.py#L95-L103). В прогоне выше все 17 вызовов без ошибок, но верных 13 из 15.

4. **Какое решение без ML записано в пяти вопросах лекции 1 и чего ему не хватает на запросах из `queries.json`?**
   Фильтры по полям каталога (язык, минуты, жанр, год). Им не хватает смысла: «как Интерстеллар, но не про космос»,
   «доброе кино», «с мамой», казахские формулировки («отбасылық», «комедия емес») — в полях каталога этих слов нет.

5. **Сколько стоит один запрос и что сильнее всего влияет на цену?**
   ≈ $0.0007 на `gpt-6-luna` ($0.0124 за 17 запросов). Цену задаёт вход: ≈ 6 450 токенов промпта (весь каталог)
   против ≈ 170 токенов ответа. Расчёт: [kino.py:32](kino.py#L32) (цены) и [kino.py:106-118](kino.py#L106-L118) (usage → $).
