# Киноманьяк

**Достигнутые уровни:** Common, Rare

Подбор 1–3 фильмов под сложный запрос **только** из локального `films.json`.  
Модель возвращает `film_id` + `why`; title / year / minutes / description печатает код из каталога.  
Rare: условия запроса (минуты, годы, язык, жанры, рейтинг критиков) разбирает модель, а проверяет код — до выбора и после.

Каркас: лекция 3 (fridge-chef) + семинар 3 (guardrails, cases, журнал).

Как проект пришёл к нынешнему виду — проблемы, данные, решения и их эффект: [DECISIONS.md](DECISIONS.md).

## Запуск

Нужны [uv](https://docs.astral.sh/uv/) и ключ OpenAI. Локальный qwen — через [Ollama](https://ollama.com) (`ollama pull qwen3.5:4b`).

```bash
uv sync
cp .env.example .env   # впишите OPENAI_API_KEY
uv run kino.py "что посмотреть с мамой на казахском, до двух часов"
uv run check.py                    # весь queries.json на gpt-6-luna
uv run check.py --local            # тот же набор на qwen3.5:4b
uv run check.py --runs 3           # три прогона подряд (сравнение моделей)
uv run show.py                     # последние 10 строк журнала и итог
uv run show.py compare             # таблица моделей из журнала
uv run filters_eval.py --local     # только разбор условий против эталона, без журнала
uv run memory_probe.py             # опыт с памятью модели
uv run build_catalog.py            # сверить каталог с Wikidata
uv run pytest -q
```

`kino.py` как `chef.py` на лекции: **без флагов** сначала `gpt-6-luna` (`reasoning_effort=medium`, так же ходит `check.py`), потом `qwen3.5:4b` (`reasoning_effort=none`).  
Облако — `parse` (Structured Outputs). Если Ollama даёт 501 — повтор через обычный `create`, JSON проверяем схемой сами.  
Без Ollama вторая модель — «Нет связи с сервером».

Пример вывода:

```
Модель gpt-6-luna
Условия: Rotten Tomatoes от 80%
Тюльпан (2008, 100 мин, Rotten Tomatoes 96%)
Молодой пастух возвращается в степь и учится жить рядом с семьёй брата.
Почему: «Тюльпан» — казахстанская драма с высокой оценкой критиков: 96% на Rotten Tomatoes.
```

### Поток `pick` (Rare)

Принцип: **модель понимает живой язык (опечатки, сленг, казахский), код сверяет то, что проверяется однозначно.**

1. **Filters** ([kino.py:86-148](kino.py#L86-L148)): первый вызов разбирает запрос в `max_minutes`, `year_from`, `year_to`,
   `languages`, `exclude_genres`, `must_genres` и сверх инструкции `min_rating` и `language_quote` (по умолчанию `None` = «условия нет»).
   Слова жанров и языков уходят в промпт тегами `<жанры>` / `<языки>` — те, что есть в переданном каталоге. В промпте —
   казахские слова жанров (тарихи → исторический, әуенді → мюзикл, отбасылық → семейный, қорқынышты → ужасы, соғыс → военный,
   күлкілі → комедия), правило «X емес» и сленг («мульт» → мультфильм, «ужастик» → ужасы).
2. **Нормализация** ([kino.py:247-292](kino.py#L247-L292)): слово не из каталога отбрасывается (`kazakh` → нет условия, а не пустой подбор);
   жанр из «не …» убирается из обязательных; больше трёх обязательных жанров = модель перечислила словарь, условие отбрасывается.
3. **Язык — по цитате-доказательству** ([kino.py:168-244](kino.py#L168-L244)). Модель возвращает `language_quote` — фразу из запроса
   дословно, с опечатками. Код проверяет: цитата **есть в запросе** (не выдумана); у неё **форма языкового оборота** («на …»,
   «по-…», «…ша», «… тілінде»), а не прилагательного страны («французская», «казахстанское», «японский»), — или это казахская
   форма с одной опечаткой («казашка» ≈ «қазақша», Дамерау–Левенштейн ≤ 1); первые буквы совпадают с языком (каз / қаз / kaz).
   Нет цитаты → запасной путь: языковой оборот в самом запросе.
4. **Отбор кодом** ([kino.py:294-340](kino.py#L294-L340)): каталог фильтруется до второго вызова. Пусто → `no_match` без вызова модели.
   Рейтинга нет в источнике → под `min_rating` фильм не проходит: условие проверить нечем.
5. **Choice**: второй вызов видит только кандидатов.
6. **Повторная сверка** ([kino.py:684-687](kino.py#L684-L687), [kino.py:414-445](kino.py#L414-L445)): каждый фильм ответа ещё раз
   проходит `passes(film, filters)`. id не из каталога → `invalid` + `rejected`; фильм не по условиям → `violations`, на экран не идёт;
   повторы схлопываются; не больше трёх.
7. Пользователь видит, как код понял запрос: `Условия: до 120 мин; язык: казахский`.

Сломанный ответ фильтров (`invalid` / `refusal` / `length`) не ломает подбор: идём без условий, это видно в журнале.
Порядок проверок в каждом вызове: API → length → refusal → schema ([kino.py:571-615](kino.py#L571-L615)).

### Журнал

На каждый вызов строка в `calls.jsonl`: модель, `step` (`filters` / `choice`), **компактный** request
(текст запроса + id кандидатов, не весь каталог), outcome, секунды, usage/$ и **конфигурация**: `effort`, `limit`
(max_completion_tokens), `prompts` (хэш обоих промптов). У строки выбора ещё `filters`, `candidates`, `shown`, `violations`, `rejected`.
Один запрос = одна строка `choice`.

### `queries.json`: ожидания и эталон

44 запроса, у каждого `expect`. Пройден — исход совпал, в ответе есть хотя бы один id из `must`, нет ни одного из `forbid`;
`no_match: true` — исход ровно `no_match`. У «қазақша отбасылық фильм» ожидание `no_match`: в каталоге нет казахоязычного фильма с жанром «семейный».

**10 запросов «как пишут люди»** (`"typo": true`): «чо посмотреть на казахкском до 2 часов», «мульт без ужастиков», «казакша комедия»,
«kazaksha drama», «фильм на англиском 90х», «советская комедя», «казашка жапондых аниме» и др.

У каждого запроса есть и **эталон `conditions`** — условия, которые в запросе есть на самом деле, по тем же правилам, что в промпте
фильтров («японский», «французская» — страна, не язык). Зачем: `violations` считаются против фильтров **самой модели**, и если она
потеряла «до двух часов», счётчик покажет 0. Против эталона `check.py` считает:

- **нарушения в выдаче** — показанный фильм не проходит настоящие условия ([check.py:64-69](check.py#L64-L69));
- **разбор = эталон** — фильтры модели оставили тех же кандидатов, что эталон (2031 как `year_from` или как `year_from+year_to` — одно и то же),
  плюс пропущенные и лишние условия ([check.py:72-91](check.py#L72-L91)).

Все ожидания `must` / `forbid` сверены кодом с кандидатами эталона.

## Каталог

**Источник фактов: [Wikidata](https://www.wikidata.org)** (CC0). У каждого фильма поле `source` — ссылка на его запись.

- `films.json`: 56 фильмов, 9 с «Казахстан» в `countries` (у «Ульжан» по Wikidata только Франция и Германия).
- [build_catalog.py](build_catalog.py) через API сущностей Wikidata забирает `year` (P577, самый ранний год), `minutes` (P2047),
  `countries` (P495), `languages` (P364) и `rotten_tomatoes` (P444 с квалификатором P447 = Rotten Tomatoes, Tomatometer в %)
  и приводит к словам каталога в коде («Соединённые Штаты Америки» → «США», «английский язык» → «английский»).
  Ранги соблюдаются: `deprecated` не берём, `preferred` важнее `normal`. Из памяти модели ничего не берётся.
- Рейтинг Rotten Tomatoes есть у 49 фильмов из 56; нет у шести казахстанских (Мың бала, Келін, Шал, Ульжан, Келинка Сабина, Рэкетир)
  и «Ивана Васильевича» — в каталоге `null`.
- `languages` — **язык оригинала**, не озвучка. «Аниме на казахском» = казахская озвучка японского мультфильма; таких данных нет,
  поэтому честный ответ — `no_match`.
- Где в Wikidata поля нет, значение и второй источник записаны в `OVERRIDES` скрипта:
  у «Келін» нет языка — фильм снят без речи ([en.wikipedia](https://en.wikipedia.org/wiki/Kelin_(film))), в каталоге `без слов`.
- Руками (и моделью) написаны только `title`, `genres`, `description` (1–2 предложения по-русски по статье Википедии).
- Обновить факты: `uv run build_catalog.py` (показать расхождения) / `uv run build_catalog.py --write`.
- `canon.py` — словарь жанров под Epic; `pick` его не импортирует.

## Пять вопросов лекции 1

1. **Какая цель у программы?**  
   Дать безопасный ответ на сложный запрос о кино без выдуманных фильмов.

2. **Как решить задачу без ML?**  
   Правила и фильтры по полям каталога (язык, минуты, жанр). Не хватает семантики вроде «как Интерстеллар, но не про космос».

3. **Какие данные нужны?**  
   Локальный `films.json`: id, title, year, minutes, genres, countries, languages, description, rotten_tomatoes.

4. **Что выдаёт программа?**  
   Разобранные условия и 1–3 карточки из каталога или `no_match` / сообщение об ошибке; журнал `calls.jsonl`.

5. **Какова цена ошибки?**  
   Показать несуществующий фильм — потерять доверие (как список книг Chicago Sun-Times); поэтому id сверяет код.
   Показать фильм на 150 минут в ответ на «до двух часов» — тоже ошибка; поэтому условия сверяет код (Rare).

## Rare: сравнение моделей

Одинаковый набор (44 запроса), одинаковые критерии (`expect_ok`, эталон `conditions`), по 3 прогона на модель
(лекция 2: ответы меняются от запуска к запуску). Записанные конфигурации (они же в каждой строке журнала):
`gpt-6-luna`, `reasoning_effort=medium`, Structured Outputs; `qwen3.5:4b` через Ollama, `reasoning_effort=none`, JSON текстом
(501 на `parse`) и проверка схемой в коде; `max_completion_tokens=4000`, промпты `8e3d7043`. Таблица — `uv run show.py compare`:

| модель | прогонов | пройдено | с опечатками | во всех 3 | разбор = эталон | нарушения в выдаче (эталон) | отсёк код | чужие id до проверки | сек / запрос | $ / запрос | $ за 3 прогона |
|---|---|---|---|---|---|---|---|---|---|---|---|
| `gpt-6-luna` | 3 | **126/132 (95%)** | 28/30 | 41/44 | 124/132 (94%) | 2 | 0 | 0 | 3.5 | 0.00045 | 0.0592 |
| `qwen3.5:4b` | 3 | **119/132 (90%)** | 30/30 | 35/44 | 112/132 (85%) | 4 | 0 | 0 | 5.7 | 0 (локально) | 0 |

Секунды и цена — сумма двух вызовов (фильтры + выбор) на запрос. `film_id` в схеме — обычная строка, не `Literal`,
так что «чужие id до проверки» мерятся честно: их не было ни у одной модели.

Что видно:

- **qwen почти догнал облако на подборе (90% против 95%) и не уступил на опечатках (30/30).** Главное отличие осталось в разборе
  (85% против 94%) и в стабильности: облако прошло 41 из 44 запросов во всех трёх прогонах, qwen — 35.
- **Эталон находит то, что не видит повторная сверка.** «Отсёк код» = 0 у обеих моделей: второй вызов видит только кандидатов,
  а сверка идёт против фильтров самой модели. Но против эталона есть 2 нарушения у облака и 4 у qwen — условие потерялось
  на первом шаге. Например, «новое кино после 2020 года» → «Душа» (2020) у qwen; «казашка жапондых аниме» → «Унесённые
  призраками» у облака: в двух прогонах из трёх luna не узнала в «казашка» язык (это и правда русское слово «казахская женщина»).
- **Где ещё теряет qwen:** «доброе кино про Алматы» 3/3 мимо «Келинки Сабины» (выбор среди верных кандидатов);
  2 ответа выбора не прошли схему `Choice` (Ollama без Structured Outputs) → `invalid`, пользователь ничего не видит.
- **Rare вылечил то, что ломалось в Common.** «До полутора часов, только не комедия» в живом прогоне Common у qwen давал
  «Кочевника» (122 мин) и «Побег из Шоушенка» (142 мин); теперь — «Келін» (82), «Рэкетир» (80), «Красавица и чудовище» (84).
- **Цена:** у `gpt-6-luna` $0.00045 на запрос против $0.0007 в Common: в промпт выбора уходит в среднем 12 кандидатов
  (≈ 2 120 токенов) вместо всего каталога (≈ 6 450). 16 запросов из 132 закончились без второго вызова — фильтры оставили пусто.

### Как мы учили qwen разбирать запрос

Первый полный замер (33 запроса) дал qwen 71% пройденных и **42%** разбора против эталона. Разбор журнала по полям показал
две повторяющиеся ошибки: **язык, которого нет в запросе — 40 раз из 99** (страну принимал за язык: «французская комедия» →
`французский`, «казахстанское кино» → `казахский`) и **казахские жанры** (не знал, что тарихи = исторический; «әуенді емес»
превращал в «не мелодрама», копируя пример из промпта).

Исправляли по принципу «понимает модель, сверяет код» и мерили каждый шаг отдельно (`filters_eval.py` — только разбор, без журнала;
эти промежуточные числа в `calls.jsonl` не попадают):

| шаг | qwen: разбор = эталон | qwen: опечатки | облако |
|---|---|---|---|
| исходный промпт (полный замер, 33 запроса) | 42% | — | 93% |
| + код проверяет язык по обороту в запросе | 76% | — | — |
| только новый промпт (глоссарий жанров, «емес», примеры без повторов) | 80% | — | — |
| оба (33 запроса) | 91% | — | 97% |
| + 9 запросов с опечатками, язык только по обороту (42 запроса) | 81% | 8/18 | — |
| **+ цитата-доказательство `language_quote`** (42 запроса) | **89%** | **16/18** | 98%, 9/9 |
| финальный полный замер (44 запроса, журнал) | **85%** | **30/30** подбор | 94% |

Почему именно цитата: проверка языка регулярным выражением ломалась на опечатках («на англиском», «казакша», «по англицки») —
код сам пытался *понять* язык. С цитатой опечатку понимает модель, а код проверяет простое: фраза есть в запросе, похожа на
языковой оборот и на название языка.

### Заметка о качестве `qwen3.5:4b`

Живой прогон автопроверки (`kino_check.py . --live`, 5 запросов, `reasoning_effort=none`) на коде Rare пройден:
«Мультфильм 2031 года», «Аватар 7» и «Қазақ тіліндегі отбасылық фильм» → `no_match`; «до полутора часов, только не комедия» →
«Келін», «Рэкетир», «Красавица и чудовище»; «как Интерстеллар но не про космос» → «Прибытие», «Она» (сам «Интерстеллар»,
который qwen показывал в Common, больше не появляется). Чужих фильмов не было ни разу.
С проверкой языка кодом, цитатой и глоссарием qwen за $0 проходит 90% набора; слабые места — разброс между прогонами
(35 из 44 запросов стабильны) и выбор по «настроению» («доброе кино»). Для черновика и офлайн-режима — рабочий вариант.

## Ответы на вопросы задания

1. **Почему программа сверяет id, хотя название понятнее? Сколько расхождений дал опыт с памятью модели?**
   Название неоднозначно (два «Гагарина», «Келін» и «Келинка Сабина»), модель может написать его по-своему или выдумать;
   id сравнивается с каталогом точно. Опыт с памятью: **5/10** расхождений по году и длительности.
   Поэтому карточку печатает код из каталога: [kino.py:448-459](kino.py#L448-L459), сравнение — [memory_probe.py](memory_probe.py).

2. **Что будет, если модель вернёт `film_id`, которого нет в каталоге? Какие строки кода это ловят?**
   Allow-list в [kino.py:414-445](kino.py#L414-L445) складывает чужой id в `rejected`; ветка
   [kino.py:691-695](kino.py#L691-L695) пишет в журнал исход `invalid` с `rejected` и возвращает `("invalid", [])` —
   пользователь не видит ни одного фильма из этого ответа. Фильм из каталога, который не проходит условия, тоже
   не показывается, но как `violations`. Тесты: `test_alien_id_invalid_and_rejected` в [tests/test_pick.py](tests/test_pick.py),
   `test_foreign_id_is_invalid_not_violation` в [tests/test_filters.py](tests/test_filters.py).

3. **Чем «модель ответила без ошибки» отличается от «модель подобрала верный фильм»? Как это видно в `check.py`?**
   Без ошибки — исход `ok`/`no_match`, схема разобрана, id из каталога. Верный фильм — в ответе есть id из `must`,
   нет id из `forbid`, `no_match` там, где ответа нет. Это проверяет [check.py:34-56](check.py#L34-L56),
   отметки ✅/❌ — [check.py:159-180](check.py#L159-L180). У qwen 130 из 132 запросов прошли без ошибки (`invalid` 2),
   но верных 119, а 4 показанных фильма нарушают условия запроса — без ошибки и без отсечения кодом.

4. **Какое решение без ML записано в пяти вопросах лекции 1 и чего ему не хватает на запросах из `queries.json`?**
   Фильтры по полям каталога (язык, минуты, жанр, год, рейтинг). Им не хватает смысла: «как Интерстеллар, но не про космос»,
   «доброе кино», «с мамой», казахские формулировки («отбасылық», «комедия емес») и опечатки («казакша», «мульт») —
   в полях каталога этих слов нет. В Rare эти фильтры есть ([kino.py:294-340](kino.py#L294-L340)), но заполнить их из живой фразы
   может только модель; код при этом сверяет её ответ (цитата-доказательство языка, [kino.py:225-244](kino.py#L225-L244)).

5. **Сколько стоит один запрос и что сильнее всего влияет на цену?**
   ≈ $0.00045 на `gpt-6-luna` ($0.0592 за 132 запроса, два вызова на запрос). Цену задаёт вход: промпт фильтров
   (≈ 1 430 токенов — правила, глоссарий, примеры) и промпт выбора с кандидатами (≈ 2 120) против ≈ 100–160 токенов ответа.
   В Common, со всем каталогом в промпте, было $0.0007. Расчёт: [kino.py:39](kino.py#L39) (цены) и
   [kino.py:385-397](kino.py#L385-L397) (usage → $).
